| File | Role |
|------|------|

## Interface

Every ZP variable in the project is defined and `.exportzp`'d by zp.s.
Modules `.importzp` what they need.  No other production source file
contains a `.segment "ZEROPAGE"` section.

This document owns the ZP allocation table and the cross-module flag
table below; other documents point here instead of restating them.

### Exported symbols ($02–$79: 117 bytes exported, 3 unallocated)

"Section" is the zp.s block the bytes are listed under; "Used by" is
every module that `.importzp`s at least one of the block's variables

Unallocated holes: $13, $2C and $36 — held so every later address
stays put; recompaction is TODO § M65, A3b.

On c64: first free byte $7A; $7A–$7F is not allocated by CSE.  Which
zero page a user program may use is
[userland_contract.md § 3](../userland_contract.md#3-memory-regions)'s
call (on c64 CSE saves and restores the whole of $00–$7F around every
user run).  `__ZP_LAST__` is generated by the linker (`define = yes` on
the ZP memory area in `src/c64_cse.cfg.in` / `src/c64_trial.cfg`) and
is the first byte past the segment; `cse_zp_end` (mem.s) returns its
low byte.

**On m65** zp.s describes CSE's own base page, `0.1F00–0.1FAF`
(`B = CSE_BP`; [platform_layer.md § Base page](../platform_layer.md#base-page)),
not base page 0, which stays the user's and the KERNAL's.  The
allocation is the table above in the same order, with three
differences; the addresses are the linker map's
(`build/<profile>/m65/cse.map`):

- **The far pointers** are declared `FAR_PTR` and are 4 bytes on m65
  (2 on c64, so the c64 addresses above do not move).  They are the
  pointers that may reach memory outside the kernel's 16-bit view
  ([platform_layer.md § Far memory](../platform_layer.md#far-memory)):
  `rp_ptr`, `rp_ptr2`, `asm_pc`, `asm_out`, `_dasm_ptr`, `disk_ptr`,
  `_io_tmp`, `gap_lo`, `gap_hi`, `buf_base`, `ed_top_ptr`, `read_ptr`
  (and its alias `save_ptr`), `ed_tmp`, `ed_scr`, and from P2 the
  screen pointers `_io_scr` and `scr_src` (the 80 × 50 screen is in
  bank 4) — 16 pointers, 32 bytes more than on c64.  The P2 banks: a
  screen pointer `FAR_BANK_SCREEN` (`scr_bank`), a source pointer
  `BANK_SRC`, the screen save's `BANK_CSE`.  How each user-memory pointer gets its
  bank (P1; [platform_layer.md § Far memory](../platform_layer.md#far-memory)):
  - `rp_ptr` — CSE's line parser (`line_buf`, bank 3) at its root in
    `exec_line`; its walks and the four restores from `expr_ptr` /
    `rp_addr` rewrite the offset only and keep that bank (no user set
    comes between: `expr_ptr` is a plain pointer the CSE map resolves);
    a user address (`FAR_USER`) in `brk_skip_user` and `step_next_pc`;
    bank 0 for the breakpoint table's targets (`patch_all`,
    `unpatch_all`); the screen in `read_line`, `main_loop`'s INS/DEL
    and `log.s`'s row tails — *stated with P2*.  A user set never
    precedes a further read of the line within one command.
  - `rp_ptr2` — a user address (`FAR_USER`) in `step_next_pc`,
    `zp_stage_prep_addr`, `cmd_dot` and `cmd_mem`; bank 3 for CSE's
    strings and tables (`parse_filename`, the segment and `prg` log
    lines; `info_emit_rows` with P2's `i`, whose m65 rows it reads) and
    for `zp_stage_prep`'s `zp_stage_buf`; bank 0 for `get_filename`'s
    `BP_ABS(cur_project_name)`.  `exec_line`'s `jmp (BP_ABS(rp_ptr2))`
    is a 16-bit jump and needs none.
  - `asm_out` — a user address (`FAR_USER`) in `dot_assemble`; bank 3
    for the assembler's `_insn_out` and `_asm_sink`.
  - `asm_pc` and `_dasm_ptr` — no set site: `asm_pc` is dereferenced
    only behind the workspace gate (bank 0, below `$C000`), and the
    product reads nothing through `_dasm_ptr` (`emit_dot` enters the
    decoder after the copy loop; `dasm_insn`'s own read serves the
    tests); their bank is the loader's 0.
- **The segment starts at `$00`:** with `B = CSE_BP` the base page's
  `$00` and `$01` are ordinary bytes.  Its first six bytes are
  `um_map`, because `hyppo_get_mapping` writes the user's `MAP`
  setting at a page start; beside them the rest of the user's bank
  state, the captured CPU port (`userland_zp_buf`, 2) and `um_d030`
  ([mem.md § Interface](mem.md#interface)) — 9 bytes, written by the
  resident stub under the user map with absolute addressing; then the
  stub's three targets (6 bytes, written by `setup_interrupts` and the
  loader).  From P2 also (the program's `SYSFLAGS`, `um_sysflags`, is
  debugger.s's BSS: no stub code touches it): the terminal's `IO_CX`, `IO_CY` (the cursor — they replace the
  `BP_PENDING` placeholders) and `io_key` (the key lookahead); the
  geometry's hot cells `scr_width` and `scr_last_col` — the rest of the
  geometry is cse_io's BSS, the base page being full
  ([platform_layer.md § Display](../platform_layer.md#display)).
- **disk.s's private pointer** (`DISK_LOCAL_PTR`) lives here — *stated
  with P3*.

The m65 segment ends below `$AD` (the linker bounds it): `$AD–$AF` is
`BP_PENDING`, the cells of the pending values — placeholders for `ST`
and `DISK_LOCAL_PTR` until P3 states them (P2 stated `IO_CX` and
`IO_CY`)
([platform_layer.md § Pending bodies](../platform_layer.md#pending-bodies));
when the last is stated, the segment's bound returns to `$B0`, where
the resident stub begins.  The KERNAL needs nothing of CSE's base page
([platform_layer.md § Interrupt frame](../platform_layer.md#interrupt-frame),
§ KERNAL calls).

### Cross-module flags

Seven 1-byte state values live here because they are read across
module boundaries, typically by a lower layer than the module that
writes them.  Hosting them in zp.s removes the back-edges that would
otherwise arise.

| Flag | Values | Writers | Readers |
|---|---|---|---|
| `in_userland` | `$80` user code running, `0` kernel | debugger.s `_rtu_body` (`$80`, on entry to user code); main.s `cse_brk_handler`, `cse_nmi_handler`, `end_debug_body` (`0`) | main.s `cse_brk_handler` (`lda`/`bne`: kernel fault vs user BRK), `cse_nmi_handler` (`bit`/`bmi`) |
| `state` | `ST_STOP` 0, `ST_REPL` 1, `ST_EDIT` 2 | main.s `reset_globals`, `refresh_body` (`ST_REPL`); editor.s `enter_editor`, `leave_editor`; repl.s `exec_line` (`Q` → `ST_STOP`) | main.s `main_loop_top`, `main_loop` |
| `warm_cont` | `1` replay `line_buf`, `0` fresh prompt | repl.s `exec_line` (`a` end-debug gate), `cmd_jmp` (`j`/`g` end-debug gate) (`1`); main.s `main_loop_top` (`0`, consumed) | main.s `main_loop_top` |
| `kernal_out` | nonzero: KERNAL banked out for a batch | asm_src.s `asm_assemble` (`1` around both passes, `0` after); main.s `refresh_body` (`0`) | mem.s `kernal_bank_out`, `kernal_bank_in` (no-op while set) |
| `ed_dirty` | nonzero: buffer modified since load/save | gap_buffer.s `gb_init` (`0`), `gb_insert`, `gb_backspace` (`1`); editor.s `ed_mark_edited`, `enter_editor`, `ed_save_source`, `ed_load_source` | editor.s `ed_render_status`; repl.s `warn_if_unsaved`, `cmd_load` |
| `dbg_reason` | enum in `src/dbg_reason.inc` (owner [debugger.md](debugger.md)) | debugger.s `dbg_init`; main.s `cse_brk_handler`, `cse_nmi_handler`, `end_debug_body`; repl.s `cmd_step`, `exec_line` (`a` success → `0`) | main.s `main_loop_top`; repl.s `warn_if_debug`, `show_break_result`, `hygiene_after_userland`, `cmd_jmp`, `cmd_step`, `exec_line` (`a` gate, `c`), `post_run_cleanup` |
| `cur_device` | floppy device number, 4–30 (cold-init 8) | main.s `reset_globals`; repl.s `exec_line` (`$ N`) | disk.s (`ldx cur_device` before `SETLFS`); repl.s `exec_line` (`$`) |

Rule: a flag lives in zp.s when at least one reader sits in a strictly
lower layer than the writer.  A flag with readers only in the same or
a higher layer stays in its module's BSS.

## Design

ZP is a global resource.  With one segment per module the layout
would be implicit and fragile — reordering link objects or adding a
byte would shift every later address.  zp.s makes it explicit: one
file, sequential `.res` allocations, address annotations in comments.
The linker assigns addresses from $02 upward; the annotations are
checked against the linker map.

### Naming convention

- `asm_*`, `sym_*`, `expr_*` — shared I/O (set by callers, read by
  callees, or vice versa)
- `_asm_*`, `_io_*`, `_st_*`, `_ex_*`, `_dasm_*`, `_as_*` — module
  scratch (the underscore prefix signals one owning module)
- `rp_*` — runtime scratch shared by repl, debugger, breakpoints, log
  and main
- `mn_c1`..`mn_c3` — mnemonic classifier inputs
- `gap_*`, `ed_*`, `buf_base`, `read_ptr` — editor / gap-buffer state

### Test stubs

Test binaries link zp.s for all ZP definitions; stubs do not duplicate
`.exportzp` / `.res` blocks.  Exception: test-only indirect pointers
that need ZP addressing (`_src_ptr`, `_buf_ptr` in
`dev/asm_src_test_stub.s`) are private ZP variables of the stub.

## Caveats

- **Link order matters**: zp.s is linked first so it owns the
  ZEROPAGE segment.  The Makefile lists `zp` first in `ASM_SRCS`.
- **mn6/mn7 alias**: `mn7_h_tmp` and `mn6_h_tmp` share address $27.
  Only one classifier is linked per build (selected by `USE_MN6`).
- **Address annotations**: the `── $XX` comments in zp.s are
  informational, taken from the linker map.  When the layout changes,
  update them from `build/release/6510/cse.map` (or `trial.map`).
