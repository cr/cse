# zp.s — Central Zero-Page Layout

**Template:** [module](../templates/module.md)

## Owned files

| File | Role |
|------|------|
| [`src/zp.s`](../../src/zp.s) | implementation — single source of truth for all ZP allocations |

## Interface

Every ZP variable in the project is defined and `.exportzp`'d by zp.s.
Modules `.importzp` what they need.  No other production source file
contains a `.segment "ZEROPAGE"` section.

This document owns the ZP allocation table and the cross-module flag
table below; other documents point here instead of restating them.

### Exported symbols (120 bytes, $02–$79)

"Section" is the zp.s block the bytes are listed under; "Used by" is
every module that `.importzp`s at least one of the block's variables
(from the code).

| Range | Section | Variables | Used by |
|-------|---------|-----------|---------|
| $02–$07 | runtime scratch | `rp_ptr` (2), `rp_ptr2` (2), `rp_tmp` (1), `rp_tmp2` (1) | `rp_ptr`: repl, main, debugger, breakpoints, log; `rp_ptr2`: repl, debugger, log, asm_src; `rp_tmp`: repl, log; `rp_tmp2`: repl |

Allocated but unused: `asm_bit` ($13; imported by asm_line, never
read or written) and `_ex_wide_tmp` ($36; no module imports it —
`expr` stacks each operand's width instead, see
[expr.md § Width propagation](expr.md#width-propagation)).  Both keep
their bytes so every later address stays put.

First free byte: $7A.  $7A–$7F is not allocated by CSE.  Which zero
page a user program may use is
[userland_contract.md § 3](../userland_contract.md#3-memory-regions)'s
call (CSE saves and restores the whole of $00–$7F around every user
run).  `__ZP_LAST__` is generated by the linker (`define = yes` on
the ZP memory area in `src/c64_cse.cfg.in` / `src/c64_trial.cfg`) and
is the first byte past the segment; `cse_zp_end` (mem.s) returns its
low byte.

### Cross-module flags

Seven 1-byte state values live here because they are read across
module boundaries, typically by a lower layer than the module that
writes them.  Hosting them in zp.s removes the back-edges that would
otherwise arise.

| Flag | Values | Writers | Readers |
|---|---|---|---|
| `in_userland` | `$80` user code running, `0` kernel | debugger.s `_rtu_body` (`$80`, on entry to user code); main.s `cse_brk_handler`, `cse_nmi_handler`, `end_debug_body` (`0`) | main.s `cse_brk_handler` (`lda`/`bne`: kernel fault vs user BRK), `cse_nmi_handler` (`bit`/`bmi`) |
| `state` | `ST_STOP` 0, `ST_REPL` 1, `ST_EDIT` 2 | main.s `reset_globals`, `refresh_body` (`ST_REPL`); editor.s `enter_editor`, `leave_editor`; repl.s `exec_line` (`Q` → `ST_STOP`) | main.s `main_loop_top`, `main_loop` |
| `warm_cont` | `1` replay `line_buf`, `0` fresh prompt | repl.s `exec_line` (`a` end-debug gate), `cmd_jmp` (`j`/`g` end-debug gate) (`1`); main.s `main_loop_top` (`0`, consumed) | main.s `main_loop_top` |
| `kernal_out` | nonzero: KERNAL banked out for a batch | asm_src.s `asm_assemble` (`1` around both passes, `0` after); main.s `refresh_body` (`0`) | mem.s `kernal_bank_out`, `kernal_bank_in` (no-op while set) |
| `ed_dirty` | nonzero: buffer modified since load/save | gap_buffer.s `gb_init` (`0`), `gb_insert`, `gb_backspace` (`1`); editor.s `ed_mark_edited`, `enter_editor`, `ed_save_source`, `ed_load_source` | editor.s `ed_status_dirty`, `ed_render_status`, `ed_mark_edited`; repl.s `warn_if_unsaved`, `cmd_load` |
| `dbg_reason` | enum in `src/dbg_reason.inc` (owner [debugger.md](debugger.md)) | debugger.s `dbg_init`; main.s `cse_brk_handler`, `cse_nmi_handler`, `end_debug_body`; repl.s `cmd_step`, `exec_line` (`a` success → `0`) | main.s `main_loop_top`; repl.s `warn_if_debug`, `show_break_result`, `hygiene_after_userland`, `cmd_jmp`, `cmd_step`, `exec_line` (`a` gate, `c`), `post_run_cleanup` |
| `cur_device` | floppy device number, 4–30 (cold-init 8) | main.s `reset_globals`; repl.s `exec_line` (`$ N`) | disk.s (`ldx cur_device` before `SETLFS`); repl.s `exec_line` (`$`) |

Rule: a flag lives in zp.s when at least one reader sits in a strictly
lower layer than the writer.  A flag with readers only in the same or
a higher layer stays in its module's BSS.

## Design

ZP is a global resource.  With one segment per module the layout
would be implicit and fragile — reordering link objects or adding a
byte would shift every later address.  zp.s makes it explicit: one
file, sequential `.res` allocations, address annotations in comments.
The linker assigns addresses from $02 upward; the annotations are
checked against the linker map.

### Naming convention

- `asm_*`, `sym_*`, `expr_*` — shared I/O (set by callers, read by
  callees, or vice versa)
- `_asm_*`, `_io_*`, `_st_*`, `_ex_*`, `_dasm_*`, `_as_*` — module
  scratch (the underscore prefix signals one owning module)
- `rp_*` — runtime scratch shared by repl, debugger, breakpoints, log
  and main
- `mn_c1`..`mn_c3` — mnemonic classifier inputs
- `gap_*`, `ed_*`, `buf_base`, `read_ptr` — editor / gap-buffer state

### Test stubs

Test binaries link zp.s for all ZP definitions; stubs do not duplicate
`.exportzp` / `.res` blocks.  Exception: test-only indirect pointers
that need ZP addressing (`_src_ptr`, `_buf_ptr` in
`dev/asm_src_test_stub.s`) are private ZP variables of the stub.

## Caveats

- **Link order matters**: zp.s is linked first so it owns the
  ZEROPAGE segment.  The Makefile lists `zp` first in `ASM_SRCS`.
- **mn6/mn7 alias**: `mn7_h_tmp` and `mn6_h_tmp` share address $27.
  Only one classifier is linked per build (selected by `USE_MN6`).
- **Address annotations**: the `── $XX` comments in zp.s are
  informational, taken from the linker map.  When the layout changes,
  update them from `build/release/6510/cse.map` (or `trial.map`).
